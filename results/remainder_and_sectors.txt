## Sectors per request: two counting models vs Nsight
# Each kernel's TTGIR layouts (ir/) replayed over every block with the exact fp32 labels of the "normal" key set
# (the kernels' own labels differ on fewer than 0.05% of keys). Both columns combine 512 sum and 4 count requests per
# block. "distinct": distinct 32-byte sectors per request. "passes": lanes that hit the same 4-byte address are
# serviced in separate passes, so a sector counts once per pass (as many times as its most-hit address). The passes
# column is a counting model that fits the counters; it is not documented hardware behavior.

          distinct   passes   Nsight
original     15.90    16.03    16.03
v3            4.00     4.12     4.12
v4           15.90    16.03    16.03
v5            4.00     4.12     4.12
v6            4.00     4.12     4.12
v8            7.16    31.90    31.90
v9            7.16    31.90    31.90
iter06        4.00     4.12     4.12
# Per request: sum atomics 16.00 / 4.00 / 32.00 under the passes model (original / flat reload / v8-v9), count
# atomics 3.39 distinct, 19.23 passes. In v8/v9 every distinct centroid row is its own sector, so whether two lanes
# share a centroid or not, each lane costs one sector access: 32 per request.
